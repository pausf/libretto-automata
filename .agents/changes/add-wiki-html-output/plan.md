# Plan — add-wiki-html-output

Durable decisions: the ones in Prior decisions of spec.md

## Summary

Split `wiki`'s write step from its extraction, then hang a second renderer off the
same `[]wikiCapability` slice: an embedded HTML template (const string, token-based
light/dark CSS, a vanilla-JS criteria filter) written to `<specs-dir>/wiki.html`
behind an HTML-comment marker. `--html` selects the renderer and the filename;
everything upstream — discovery, parsing, the empty/missing refusals — is the
existing code, untouched. A plain run additionally refreshes a marked `wiki.html`
when one exists, so record-work's landing instruction covers both views with the
sentence it already has.

## Technical context

- Base: branch `feat/add-wiki-html-output`, chained on `feat/add-specs-wiki`
  (PR #66, unmerged) — `wiki.go` and its seven tests exist only there, not on
  `main`. The PR for this change targets that branch until #66 merges.
- Go 1.26.5, stdlib only: `html` (escaping), `strings`, the existing `bufio`
  extraction. The template is a `const` in `wiki.go` — no `embed`, no asset file,
  one consumer.
- Blast radius: `cmd/libretto/wiki.go` (renderer + flag + refresh logic),
  `cmd/libretto/wiki_test.go` (eight new tests), `cmd/libretto/main.go` (pass
  `args[1:]` to `wiki`), usage text, one AGENTS.md line. Four files, none new.
- Gates: the six. **Which rule wins mid-branch, stated because the cutter asked:**
  the delta's citations exist before their tests, so `--anchors` is red between
  the contract commit and box 1's commit — the same window the parent change had.
  The cut answers it structurally: box 1 carries all nine tests, so no commit
  after it can be red for this reason, and no box is split in a way that reopens
  the window.
- Fonts, named (a builder decision the cutter refused to make silently):
  Fraunces (display; Georgia, serif fallback), Public Sans (body; system-ui,
  sans-serif), IBM Plex Mono (code; monospace) — the demo's trio, loaded from
  `fonts.googleapis.com` with those fallback stacks declared on every face.

## The approach

1. **Refactor the seam**: `wiki(w, projectDir, args)` parses `--html` (anything
   else is an error); extraction stays as is and returns `[]wikiCapability`; the
   write step becomes `writeMarked(path, marker, render)` — read first line,
   refuse foreign, write, shared by both outputs.
2. **The HTML renderer**: `renderWikiHTML(projectDir, caps)` fills the embedded
   template — first line `<!-- generated by libretto wiki; edit the specs, then
   run: libretto wiki --html -->`, then inline CSS (tokens on `:root`,
   `prefers-color-scheme` dark block), sidebar nav (name + criteria count),
   sections (intro, `Governs:`, criteria list), inline filter script. Every
   spec-sourced string passes through `html.EscapeString`; the bold/backtick
   inline markup is converted *after* escaping, on the escaped text, so no raw
   spec byte ever reaches markup position.
3. **The refresh rule**: after a plain run writes `README.md`, it stats
   `wiki.html`; present with the HTML marker → re-render and rewrite it; present
   without → skip silently; absent → nothing. `--html` is the mirror image and
   touches only `wiki.html`.

## The alternatives it beat

| Considered | Why it lost |
|---|---|
| `--serve` (net/http over the specs) | A static file already reaches the browser via `file://`; a daemon adds a lifetime to manage and buys a URL nobody asked to share. Comes back if someone needs other people to open it. |
| `html/template` over string building | The template has one consumer and no user-controlled structure; `html/template`'s contextual escaping would double-escape the pre-escaped inline markup and its real payoff — many templates, many authors — is absent. Manual `html.EscapeString` at the one boundary is smaller and the escaping criterion pins it. |
| A separate `wiki-html` subcommand | Two commands over one extraction is two entries in every table (usage, AGENTS.md, panel) for one feature; a flag on the existing family member matches `prune --yes` precedent. |
| Regenerating HTML only ever explicitly | Leaves the landing refresh stale unless record-work names `--html`, which is a second payload sentence that can drift from the set of outputs. The refresh-what-is-marked rule keeps the instruction closed under new views. |
| Waiting for PR #66 to merge first | An idle day for nothing — chaining is what AGENTS.md says independent branches do, and the diff stays reviewable on its own. |

## Risks

| Risk | What catches it |
|---|---|
| Escaping done in the wrong order (markup conversion before escape) turns a spec's `<script>` into live script | `TestWikiHTMLEscapesSpecContent` feeds a fixture criterion carrying `<script>alert(1)</script>` and asserts the output contains the escaped text and not the raw tag. This is the test to force red first. |
| The plain-run refresh erroring on a foreign `wiki.html` blocks landing regeneration everywhere | Settled in the spec (skip silently); `TestPlainWikiRefreshesAMarkedHTMLView` carries the foreign-file subcase. |
| Template drift between the two markers (md vs html) breaks ownership detection | One `writeMarked` helper owns the read-first-line check for both; the marker constants sit beside each other. |
| Google Fonts links make the page look broken offline | Fallback stacks declared on every face; the self-contained test forbids any other external reference, so offline degrades to system fonts and nothing else is missing. |

## Validation and rollback

`go test ./cmd/libretto/` carries the eight new tests; all six gates per commit.
The test to force red on purpose is `TestWikiHTMLEscapesSpecContent` — an escaping
bug passes every other test silently and is the one with a security shape. Rollback:
one revert; nothing migrates, and a generated `wiki.html` in any project is
identified by its marker and regenerable or deletable freely.

## Complexity deliberately kept

The two-marker `writeMarked` seam is more indirection than two inline checks, and it
stays: ownership refusal is the most defended rule in the repository, and one
implementation of "is this file ours" is one place for that rule to be wrong.
